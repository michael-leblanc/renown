# Scripts

One line per script: what it does and how to run it.
Agents read this list before doing repeated work by hand.

| Script | What it does |
|---|---|
| `scripts/godot.sh <args>` | Runs the pinned Godot 4.7.2 (D1). Downloads it once into the per-user cache (`~/.cache/renown/godot/4.7.2-stable/`, `RENOWN_GODOT_CACHE` replaces the `~/.cache/renown/godot` part); every worktree shares it. Editor: `scripts/godot.sh --editor --path game`. |
| `scripts/verify.sh` | The gate: imports the project, parse-checks every `.gd` under `game/`, runs the GUT tests (a runtime error in a test or a fixture hook, or zero tests run, is FAIL). Prints `PASS`, or `FAIL: <step>` with `file:line` and the test name. Exit 0 / 1. |
| `scripts/measure.sh [--count=N]` | The tick-time measurement (D184, D186): one line per NPC count (32 to 8000) with the average tick, the worst tick and the state hash, then the NPC budget (largest count with a worst tick under 20 ms), the CPU, the OS and the Godot version. `--count=N` measures only that count. Run it with nothing heavy going. Takes several minutes. |
| `scripts/check_parse.sh` | Used by `verify.sh`: loads every `.gd` outside `addons/` in one Godot process (`check_parse.gd`), because import and GUT miss a parse error in a script no test loads. |
| `scripts/check_test_names.sh` | Used by `verify.sh`: fails on a file under `game/test/` not named `test_*.gd` (GUT would skip it). Helpers go in `game/test/helpers/`. |
| `scripts/test_verify_on_stop.sh` | Proves `.claude/hooks/verify-on-stop.sh` on a fake project: a failing implementer is blocked (exit 2, failures shown), other agents and a passing implementer exit 0. Prints `PASS`. |
| `node scripts/art/props.mjs [names\|all] [--draft] [--beside "<piece>"] [--with-character] [--views S,E,N,W] [--ss N] [--out dir]` | Draws the test game's code-made standing stones (D71), chests (D54), crate and barrel into `prototype/art/made/`: 256 x 256 PNGs in the tileset's format, 4 sides, plus ground shadows. Under 2 seconds a sprite. `--draft` writes no sprite: it saves one picture to look at, `prototype/shots/art-draft.png`, with `--beside` adds a tileset piece and prints both pictures' brightness, and with `--with-character` adds a human on the next tile, for size. Shapes are maths in the script, drawn by the kit `scripts/art/kit.mjs`; how to write a new prop is in `.claude/skills/renown-prop/SKILL.md`. No package needed. |
| `node scripts/art/camp.mjs [names\|all] [same flags as props.mjs]` | Same for camp gear: a lit campfire in a ring of stones and a canvas ridge tent (about 2 tiles long), into `prototype/art/made/`. About 5 seconds a prop. |
| `node scripts/art/furniture.mjs [names\|all] [same flags as props.mjs]` | Same for furniture inside shops and homes (D35, D208): a table, a stool, a bed (about 1.5 tiles long, a hide for a blanket), a shop counter and a tall shelf with goods on it, into `prototype/art/made/`. About 3 seconds a prop (the shelf about 7). |
| `node scripts/art/shore.mjs [names\|all] [same flags as props.mjs]` | Same for Dawndoor's shore (D113): `Jetty A1` (one tile of plank deck on four posts, open at both ends so tiles join in a row) and `Jetty End A1` (the last tile, with a mooring post and rope), into `prototype/art/made/`. About 8 s. |
| `node scripts/art/village.mjs [names\|all] [same flags as props.mjs]` | Same for plain town and camp things the tileset lacks: `Fence A1` (split rails on the tile's far edge, like a wall), `Bedroll A1`, `Log Seat A1`, `Chopping Block A1`, `Fish Rack A1`, `Net Poles A1`, `Campfire A1 Out`. About 30 s. |
| `node scripts/art/anim.mjs [names\|all] [--draft] [--views S] [--out dir]` | The animated ones, into `prototype/art/made/anim/`: per side one strip of frames side by side (each 256 x 256, tile middle at 128,208), one still shadow, and `anim.json` with each one's frames, frames a second and sides. Fire (flames that sway and stretch in a loop, no shadow): `Campfire A1 Lit` (with sparks), `Torch A1`, `Wall Torch A1` (far edge), `Brazier A1`, `Lantern Post A1`, `Cooking Fire A1`, `Table A1 Candle`, `Hearth A1` (far edge), `Forge A1` (coals that breathe, bellows). Cloth: `Pennant A1`. Ground tiles drawn in 2D, seamless and looping: `Water A1` (deep), `Water A2` (shallow), `Water Shore A1` (foam on one edge; the side names it), `Water Shore Corner A1`, `Water Shore Inner A1`. Effects with no shadow: `Smoke A1`, `Smoke A2` (from a chimney), `Steam A1`, `Ripples A1`, and for a character `Block Flash A1` (D207), `Hit Spark A1`, `Miss Puff A1`, `Bandage A1` (D164). Played once, the last frame held (`loop: false`): `Chest A1 Opening`, `Door A2 Opening` (a plank door in a timber frame on the far edge). Turning or flapping: `Water Wheel A1` (512 px picture, against a mill wall; 32 frames for an eighth of a turn, made to be blended frame to frame; `Water Wheel A1 Under` is its part below the water, for drawing through the water, and `Water Wheel A1 Foam` the white water exactly along its waterline, 16 frames each), `Windmill A1` (a post mill, 1024 px picture), `Market Stall A1`; the two mills at about 0.6 of real size. `Light A1`: a white light texture for the game's PointLight2D, real falloff, dithered in 8 steps. Weather, whole-screen squares that repeat: `Rain A1` (two layers of slanted streaks), `Rain Splash A1`, `Fog A1` (512 px, one frame, scrolled), `Leaves A1` (tumbling). Open water's surface, two seamless 512 px squares for a world-space water shader: `Water Base A1`, `Water Glints A1`. `--draft` puts the first side's frames in a row in `prototype/shots/anim-draft.png`. About 10 min for all. How to add one: `.claude/skills/renown-anim/SKILL.md`. |
| `node scripts/art/scene.mjs [--out file.html] [--place place.json] [--on Night,Rain,Wet,Near] [--shot [file.png]] [--wait 4] [--scale 2]` | One page to try a place on a phone, `prototype/shots/scene.html` (about 5 MB): a 14 by 14 patch (Night, Rain, Fog, Leaves buttons; rain and leaves fall to real spots and splash, ripple, lie or float) where you place ground (the tileset's, plus stand-in water and sand), tileset pieces, every code-made prop, every item and the three races; Turn (sides, metals, facing), Erase, Walk (tap a tile, the character walks there at 0.6 s a tile), Look (names), pinch to zoom, Save in the browser. `--place` opens it on a place written in a file (format in the skill `renown-anim`), `--on` presses its buttons (`Wet`: already wet), `--shot` takes a phone-sized picture with headless Chrome (`prototype/shots/scene.png`; about 45 s with rain). About 15 s. It holds bought art (tileset, Creator): never commit it. |
| `node scripts/art/effects.mjs [--out dir]` | Effects the client draws over the world, into `prototype/art/made/effects/`: `Arrow Flight.png` (one arrow in the air pointing right, its middle at 128,128, no shadow; the client turns it toward the target, D163), and the waking glow (D89) as two strips of 8 frames of 256 px, 8 a second, the tile's middle at 128,208 in each frame like a prop: `Waking Glow.png` (a pale gold ring round the feet, drawn under the character) and `Waking Glow Front.png` (motes rising past it, drawn over it). About a second. |
| `node scripts/art/doorway.mjs [outdir] [S,E,N,W] [supersample]` | Same for the lone stone doorway (D108). Written before the kit: about 22 seconds a side. |
| `node scripts/art/colours.mjs "<piece>" [how many]` | Lists the colours a tileset piece uses most, dark to pale: the start of a new colour ramp for the kit. `scripts/art/png.mjs` reads and writes the PNGs. |
| `node scripts/art/items.mjs [names\|all] [--out dir]` | Draws the agreed items (D218; the `ITEMS` list: long sword, axe, mace, spear, three shields, short bow, longbow, arrows, quiver, tunic, leather tunic, platebody, hood, helmet, great helm, trousers, leather trousers, shoes, metal boots, gloves, gauntlets, backpack, bedroll pack, bandage, sack, coins) into `game/client/art/made/items/`: 256 x 256 PNGs like the props but one side only. Each item has a ground picture (lying in the world; clothes laid flat, the UO way), one per metal (`Axe Bronze.png`) or dye (`Tunic Blue.png`), each a colour swap of one drawing, and one ground shadow (`Axe Shadow.png`); and a pack picture of the same name in `items/pack/` (the drawing turned to face the viewer and fitted to a 46 px slot, the RuneScape way, its middle at 128,128, no shadow; shields, helmets, footwear, backpacks, bandage and coins keep their ground picture; the sack is never in a pack, so it has none). Stops if an item reaches the picture's edge. About 25 s for all. Also writes one picture to look at, `prototype/shots/items.png`: the sprites at game size beside the test game's human and the chest, then each 3 times the size, on the ground and in a pack slot. `--draft` writes no sprite: three designs of each sword, shield and coin pile in `prototype/shots/items-draft.png`. Its `MATCHED` list says which Creator part each held item is the picture of. |
| `node scripts/art/items_page.mjs [--items dir] [--out file.html]` | One page to look at the items on a phone, `prototype/shots/items.html`, read from the sprites `items.mjs` wrote (run that first): the items on grass round a human (zoom, tap for a name), a pack, and a card per item with its ground and pack pictures and its metals or dyes. Under 5 s. It holds bought art (the grass tile, the Creator body): never commit it. |
| `node scripts/art/dirs.mjs <part sheet .png>... [--body <NakedBody sheet>] [--frame N] [--out file]` | Shows Creator parts from all 8 sides, enlarged, in one picture (`prototype/shots/dirs.png`), and prints each side's size and the part's grey levels. Run it before drawing an item from a part. |
| `node scripts/art/reskin.mjs <folder of part sheets> <out folder> [--only parts] [--metal bronze] [--unsure N]` | Repaints the matched Creator weapon and shield sheets pixel for pixel in the item pictures' colours (D219), every animation it finds: `<out>/<Part>/<Animation>.png`, laid out like the Creator's own folder. A part that comes in metals (sword, axe, mace, spear, metal shield) is painted in iron's six colours: whoever draws it swaps them for the six of the item's metal (D225; the colours are `METAL` in `items.mjs`). `--metal bronze\|iron\|steel` paints that metal in instead, into `<out>/<Part>-<metal>/`: the same pixels the swap gives. The folder is the Creator's own `Spritesheets` folder or one laid out like it; a part with no sheet is skipped. About 20 seconds for 5 parts and 30 animations. For axe, mace and spear it finds the head by shape, settles each row of frames together, leaves a hidden head unpainted, and prints a check (a thick clump at the butt's half painted as haft: should be 0 frames); `--unsure N` lists the rows to look at by eye. The results are bought art repainted: never commit them. |
| `node scripts/art/held.mjs <Creator folder> <repainted folder> [--only parts] [--dirs SE,S,SW,NE] [--shots Idle:S:0,Attack1:SE:6] [--z N] [--out file]` | The picture an item is judged from (`prototype/shots/held.png`): the test game's human at game size holding each repainted part in the metal `MATCHED` names for it (swapped in here, D225), with the item's picture on the ground beside it. A column is a shot (animation, side, frame); `--shots` needs the body's sheets for those animations in the Creator folder. Run `reskin.mjs` first. |
| `node scripts/art/play.mjs <Creator folder> <repainted folder> [--start Melee24,Attack6,steel] [--races human,orc] [--wear] [--anims Idle,Attack3] [--walk-seconds 0.6] [--out file.html]` | The way to judge a repaint in motion: one page (`prototype/shots/held-play.html`, open it in a browser) that plays the test game's characters holding the repainted parts, at the game's size and speed. Race: human, orc or goblin at their sizes (D205; tints and sizes from `character_data.json`), and a skeleton when the Creator folder has its body (`NakedBody2`; a stand-in look), each from all 8 sides, or all side by side from one side. Pick the weapon, its metal (the page swaps iron's colours as the game does, D225), the shield and the animation (the attacks listed first); pause and step frame by frame. It offers every animation the human body's sheets are there for (9 with `prototype/art/creator/`, all 30 with the Creator's own `Spritesheets` folder). The sheets are inside the page (about 7 MB with 17 animations and 4 races; `--races` makes it smaller): bought art, never commit it. `--wear` adds a choice and a colour for every worn Creator part, listed by the plain names in `scripts/art/creator_parts.json` (the Creator part number on hover), and a Preset list of whole looks from `scripts/art/creator_presets.json` (an archer, an orc in heavy armour, a knight and so on; add one as a row) (head, chest, legs, shoes, hands, belt, back, hip) and the 7 bows (a bow shoots with `Attack3`); those sheets are read from the Creator folder by a path relative to the page, not put inside it. Walk plays at `--walk-seconds` a tile (0.60) and Run at the test game's 0.30, each at one pace on every side, the rate that keeps the foot on the ground on a straight grid step (D226, D227; Run's stride is an estimate). Run `reskin.mjs` first. |
| `node scripts/art/swap_check.mjs <Creator folder> <work folder> [--only parts] [--anims Attack1,Walk]` | Checks the colour swap of D225 in Godot itself: every held sheet in iron's colours, drawn through `scripts/art/swap_check/swap.gdshader` with bronze's and steel's colours, against the same sheet with the metal painted in (`reskin.mjs --metal`). One line per part and metal (`0 of N drawn pixels differ`), then `PASS` or `FAIL`. About 80 seconds for 4 weapons and 30 animations. It draws, so it needs a screen (on Linux with none it runs under `xvfb-run`). `swap.gdshader` is the shader the client uses for held parts. The work folder holds bought art repainted: git-ignored folders only. |
| `node scripts/art/ui/character_screen.mjs [--out dir]` · `--draft [--shot file.png] [--scale 2]` · `--page [--to file.html]` | The character screen's pieces (D239 to D241), into `game/client/art/made/ui/`: `Frame` (slate panel and steel trim, 620 x 760), `Stage`, `Satchel`, `Strap`, four `Medallion <stat>`, and `Slot <kind> <material>` (kinds Gear, Hand, Pack, Round; a material or Empty), 31 PNGs, plus `character_screen.json`: where every piece, slot, item picture and line of text goes, for Godot to read. Text is not a piece: Godot draws it in Alegreya (`game/client/art/fonts/`, OFL 1.1). About 4 s. `--draft` writes no piece: it puts them together the way the json says, with the test game's human, item pictures and made-up numbers, into `prototype/shots/ui-character-screen.png`. That picture holds bought art (the Creator character, the grass tile): never commit it. `--page` writes one web page, `prototype/shots/ui-character-screen.html` (about 1 MB, nothing loaded from outside): it reads the pieces and the json from `--out` and draws the screen from them at any size (Fit, 1x to 3x, pieces only), with the text drawn by the browser in Alegreya; it holds the Creator character too, so never commit it. Written with `scripts/art/ui/kit.mjs` (the screens' look, D240: noise, shapes, metal, shrinking; for the next screens too) and `scripts/art/ui/text.mjs` (reads the .woff fonts, for check pictures only; no kerning). No package needed. |
| `node scripts/plan.mjs` | Plan status, `validate`, `graph`, `show <id>`, `set <id> <status>`. |
