# QA NET-001: PASS

Checked by reading the diff (`HEAD~1..HEAD`) and the tests. I didn't run the red proof, since the task isn't critical.

- **Acceptance:** each of the 9 criteria has a test with real assertions in `game/test/server/test_view.gd` or `game/test/net/test_messages.gd`.
  - The sight cases cover a wall edge, a blocking tile and 17 tiles away, each with a clear control character.
  - The doors test covers open, closed and out of sight.
  - The sight-rebuild count is asserted as 1 for two views in one tick, then 2 after `sim.step()`.
- **Edge cases:** a viewer id that isn't in the world gets an empty view. `stepping_onto` returns null once a walk ends, because the walk is erased. The viewer is never listed twice, because `in_sight` skips the viewer's own id. Characters on the same tile as the viewer are not a problem.
- **Domain rules:** `game/net/messages.gd` names no `sim/` class, and a test checks that. `view.gd` is a `RefCounted` under `server/`. The added `movement.gd` accessor is read-only. No numbers are hard-coded: the tick rate and walk time come from settings. There is no clock and no randomness. The view sends no brain, target or order.
- **UI and UAT:** neither applies (`uat: false`, and there is no UI yet).

Minor notes, not blocking:
- `ServerView` caches sight per tick. A character added mid-tick won't show up until the next tick or an `invalidate()` call.
- `rescan_edges()` has to be called by hand when a door or wall is added.
