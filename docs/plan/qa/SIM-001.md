# QA SIM-001: PASS

All four acceptance criteria have a test that would fail if the behavior were wrong:
- 10 ticks per second and 2 s gives 20 ticks. 20 ticks per second and 2 s gives 40.
- 0.34 s gives 3 ticks, 0.36 s gives 4, and 0.01 s and 0 s both give 1.
- A missing timing or value calls `push_error` with its name. The test checks this with `assert_push_error`.

Domain rules hold: `SimSettings` extends `RefCounted`, uses no clock or randomness, and writes no number in code. The numbers live in `game/data/settings.json`.

Red proof was not run. The task is non-critical and the implementer's report didn't say `red: no`. The code and tests are both new, so the tests can't pass without the code.

Non-blocking notes:
- If `tick_rate` is missing from the data, `from_dict` logs an error and returns `tick_rate` 0. After that, `ticks()` returns 1 without a further error. No test covers this path.
- `settings.gd.uid` and `test_settings.gd.uid` are not in `touches`. Godot generates them, so this is fine.
