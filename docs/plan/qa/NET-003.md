# QA NET-003: PASS

Each of the 8 acceptance criteria has a test in `game/test/server/test_orders.gd` that checks the real outcome:
- Walk: same end tile as a twin sim given the order directly, and the other character doesn't move.
- Blocked or unreachable: position unchanged and `pathing.searches` unchanged.
- Door: character at the door tile and the door open.
- Replacement: the second order's target is reached.
- No character id: a forged `id` in the message is ignored.
- Bad input: 9 malformed shapes each counted in `dropped`, with the character still in place.
- Rate limit: per-peer allowance that resets after one second of ticks.
- Never welcomed: dropped through `NetServer._on_order`.

Domain rules hold. `orders.gd` is `RefCounted`, uses no clock or randomness, and passes the connection's character id instead of one from the message. The limit is in `settings.json`, and the window follows `tick_rate`.

Not done:
- **Red proof:** not run. The Edit tool was disabled, and the task is non-critical.
- **UI e2e and UAT:** not applicable (`uat: false`, no UI).

Minor and not blocking: `orders.gd` has `kind ==NetMessages.ORDER_WALK`, missing a space after `==`.
