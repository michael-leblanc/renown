# PRO-005 review

## Review: PASS
1. **Standing forces Idle every frame** — prototype/play/play.gd:226. `tick()` calls `human.set_anim("Idle")` on every tick the human isn't stepping. `set_anim` restarts Idle whenever another animation is playing, so in PRO-006 Attack1, TakeDamage, the block candidates and Die (which has to hold its last frame) would be cut off one frame after they start. This is fine for PRO-005. In PRO-006, set Idle once when a walk ends (in `_end_step` when `path` is empty) or when a click is refused, not on every tick.
2. **Corner rule is stricter than D185 by default** — prototype/play/play_data.json:17, prototype/play/pathfinder.gd:52. D185 forbids only a diagonal step between two blocked tiles. The default `diagonal_needs_both_sides_free: true` also forbids passing the corner of one tree or wall. The acceptance is still met, because strict covers the D185 case, and the README flags the difference. But Michael's walk-feel verdict in the PRO-006 UAT will be given under a rule nobody decided. The fix is cheap: either turn the default to D185's reading, or have the PRO-006 UAT ask about it so the lesson comes back as a decision, not as an unnoticed default.

Notes (not defects):
- **Launch:** Michael can launch play with one command: `scripts/godot.sh --path prototype res://play/play.tscn`. I ran it (headless, `--quit-after 30`): it loads with no errors and exits 0. No main scene is set, so `scripts/godot.sh --path prototype` alone fails with "no main scene defined" (and when headless it did not exit by itself). That matches prototype/README.md's "run a scene by path" convention. Setting `run/main_scene` is optional and would make the bare command and the editor's F5 work.
- **Checks:** `check.gd` printed ALL OK (exit 0). The shortest-path check compares against a separate BFS on 36 walks over 3 seeds, the corner check covers 545 real diagonals, and the door check covers 4 seeds. These checks prove the acceptance. They don't just mirror the code.
- **Ready for PRO-006:** Pathfinder only goes to an exact tile. That fits "walk next to the dummy" because characters are not obstacles (D52, D187): PRO-006 picks a free neighbouring tile and must not end on the dummy's tile. The walk state (`cell`, `path`, `moving`) sits on play.gd for the one human. That is fine while the dummy stands still.
