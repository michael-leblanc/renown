# QA SIM-003: FAIL

All 5 acceptance criteria have a test that proves them. I ran the headless server with `--tick-limit=50`; it printed `ticks: 50`. `sim.gd` reads no clock and has no nodes. The issues below are an edge case and a domain-rule breach.

## Issues
1. **Tick rate 0 divides by zero** — game/server/clock_loop.gd:15. `SimSettings.from_dict` returns `tick_rate = 0` when the setting is missing, or when the file says 0 or a negative number. Then `1000000 / sim.settings.tick_rate` is an integer division by zero. Expected a clear error that names `tick_rate`, and no crash. Got a crash. Fix: in `ClockLoop._init`, `push_error("tick_rate must be above 0")` and keep `_tick_usec` safe, so `pump` returns 0. Make `server_main.gd` quit(1) when `tick_rate <= 0`. Add a test for each.
2. **Numbers written in code** — game/server/server_main.gd:22-23. `SimWorld.new(64, 48)` and `Engine.max_fps = settings.tick_rate * 4` are made-up numbers. "Every number is a setting" (D175) says they belong in `game/data/settings.json`. Fix: add `world_width`, `world_height` and `max_fps_per_tick` (or similar) under `values`, and read them with `settings.value(...)`.
